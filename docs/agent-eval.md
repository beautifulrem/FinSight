# FinSight Agent Evaluation

This page reports how the agent layer (`query_intelligence/agent/`) performs end to end, how the numbers were produced, and what they do **not** show. Every number in the generated section below comes from a reproducible run; the commands, commit, and date are printed with the tables.

## What is measured

| Item | Where |
|---|---|
| Development task set: 207 tasks / 220 turns, 11 categories, Chinese and English | `evaluation/agent_eval/tasks/agent_eval_v1.jsonl` (built by `build_tasks.py`) |
| Held-out task set: 53 tasks / 56 turns, new phrasings, written after the development set was used for fixes and never used for tuning | `evaluation/agent_eval/tasks/agent_eval_holdout_v1.jsonl` (`build_holdout.py`) |
| Point-in-time tool snapshots (replayed so results do not depend on live providers) | `evaluation/agent_eval/fixtures/snapshot_v1.json`, `snapshot_holdout_v1.json` |
| Scoring | `evaluation/agent_eval/metrics.py` |
| Ablation over answer paths | `evaluation/agent_eval/ablation.py` |
| Fault injection | `evaluation/agent_eval/fault_injection.py` |

Categories: single facts, comparisons, "why" questions, macro-to-market links, missing data, technical indicators, documents and sentiment, multi-turn follow-ups, out-of-scope refusals, clarification, and compliance traps (requests for buy/sell calls, price targets, all-in positions).

Expected facts come from the shipped offline snapshot (`data/structured_data.json`, market data as of 2026-04-22), so every required value is checkable. Queries were written for this evaluation and checked against the 1,112 queries used for training or other evaluations in the repository (no exact overlap).

**Scoring is dealbreaker-gated**, in the spirit of finance-agent benchmarks: a turn succeeds only if the behaviour is right (answer / clarify / refuse), every required fact is both stated and cited with the right evidence id, required tools were used, no trading instruction appears, and hedging, missing-data honesty, and entity carry-over hold where the task requires them. `pass^k` counts a task as solved only if all `k` repeated runs succeed.

## Answer paths compared

| Path | What it is | Needs an LLM |
|---|---|---|
| `legacy` | The original `/chat` path (Query Intelligence pipeline + template answer, as served when no LLM key is set). Its refuse/clarify behaviour is inferred from NLU flags, which is generous to it. | no |
| `workflow` | Agent: classical NLU guard and router, deterministic planner, tools, template composer, evidence verifier, compliance guard. | no |
| `pure_llm` | The LLM answers with no tools. | yes |
| `legacy_llm` | The original `/chat` path with DeepSeek rewriting the evidence. | yes |
| `workflow_llm` | Agent workflow with the LLM composing the answer from tool evidence. | yes |
| `agent` | Agent with the LLM choosing tools in the LangGraph loop. | yes |

## How to read these numbers

* **Offline only.** This environment has no LLM API key and no network access to market data, so only `legacy` and `workflow` were run. The `pure_llm`, `legacy_llm`, `workflow_llm`, and `agent` columns — and therefore any claim that the LLM tool loop beats the fixed workflow — require running `python -m evaluation.agent_eval.ablation --llm deepseek --repeats 3` with `DEEPSEEK_API_KEY` set. No LLM results are reported here.
* **The legacy path is built around its LLM.** Without a key, its template answer only summarizes what was retrieved ("已读取 3 条结构化数据…") and does not state values, which is why its fact recall is low offline. The comparison shows what the new tool, verifier, and compliance layers add *when no LLM is available*; it does not show how the legacy path performs with DeepSeek.
* **The development set was used for fixes.** The first development run scored 77.3% task success; failure analysis led to agent-layer fixes (out-of-scope overrides for macro/finance anchors, dangling-reference clarification, lexical hedging triggers, planner pruning, honest indicator availability). The held-out set was written afterwards and run once; the gap between the two sets is the honest estimate of how much of that improvement generalizes.
* **Template answers are deterministic restatements of tool output.** High fact recall and 100% draft verification in `workflow` mean the pipeline retrieves, cites, and guards correctly; they do not measure reasoning quality, which only an LLM path can add.
* **The snapshot is small.** Seven symbols have market data, three have fundamentals, four macro indicators. Entities outside it are used deliberately as "missing data" tasks.

## Known failures and root causes

* English company names without aliases in the entity master (e.g. CATL, BYD, China Merchants Bank, CITIC Securities) are not resolved, so their "missing data" tasks fail the required-tool check. Root cause: alias coverage in `data/runtime/alias_table.csv`, not the agent.
* On the held-out set, lexical hedging triggers miss some phrasings (e.g. 抄底, 翻倍, 止盈点位), and some fact phrasings are not mapped to the right tool. These are left unfixed on purpose so the held-out number stays honest; they are the next rules to generalize.
* The classical NLU still labels some finance questions out-of-scope (e.g. "最新一期PMI数据是多少？"); the agent corrects these with explicit, logged overrides rather than hiding them.

## Reproducing

```bash
python -m evaluation.agent_eval.build_tasks           # regenerate the development set (checks training overlap)
python -m evaluation.agent_eval.build_holdout         # regenerate the held-out set
python -m evaluation.agent_eval.runner --mode workflow                      # development set, offline
python -m evaluation.agent_eval.runner --mode workflow --record             # re-record the tool snapshot
python -m evaluation.agent_eval.ablation                                    # legacy vs workflow, both sets
python -m evaluation.agent_eval.fault_injection                             # graceful-degradation scenarios
python -m evaluation.agent_eval.report                                      # refresh this page
# online (requires DEEPSEEK_API_KEY and network access):
python -m evaluation.agent_eval.ablation --llm deepseek --repeats 3
```

To report cost, set `QI_LLM_PRICE_INPUT_MISS`, `QI_LLM_PRICE_INPUT_HIT`, `QI_LLM_PRICE_OUTPUT` (per million tokens) and `QI_LLM_PRICE_CURRENCY` to the provider's current prices before an online run; token counts are always recorded.
