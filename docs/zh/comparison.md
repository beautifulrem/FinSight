# FinSight 与同花顺问财、豆包、Kimi、Wind Alice（及东方财富妙想）的对比

语言：[English](../comparison.md) | 中文

这一页用来回答评审提出的问题：“为什么不直接用豆包？”资料截至 2026-09-26，全部来自公开渠道。**这些产品我们一个都没有实际跑过**：没有注册账号，也没有使用 API Key。所以文中关于它们的每一句话，都出自厂商页面、官方公告或媒体报道，并标注来源编号 `[S#]`（链接和日期见文末[来源列表](#来源)）。查不到的内容一律写作“**未公开/未核实**”。FinSight 的数字出自 [Agent 评测报告](../agent-eval.md)（commit `846bc5e`，DeepSeek V4.1 Flash，每个任务跑 3 次）。

## 一句话回答：为什么不直接用豆包或问财？

如果只是查个价格、筛几只股票、快速看懂一份公告，直接用问财、Wind Alice 或 Kimi 就好。它们有持牌的实时数据、宽得多的覆盖面、成熟的 App 和上百万用户，这些 FinSight 一样都没有，它也不打算取代这些产品。FinSight 是一个开源的参考实现，只做一件事：这些产品都说自己“可溯源”，但没有公开量化过；FinSight 则**由代码逐句检查答案里的每个数字，确认它出现在同一句引用的证据里**，并且公开校验器自身的误差：在 3,399 个被篡改的答案上误放率 1.94%，202 个正确答案无一误杀。在此之上，它还有一道硬性的合规关口，评测全部公开，可以私有化部署，并能通过 MCP 和 A2A 调用。“为什么不用豆包”这半个问题，我们有一个实测过、但只能部分说明问题的答案。通用大模型不接工具直接作答（评测里的 `pure_llm` 基线），在一票否决的评分下 **381 个任务一个都没过**（开发集、保留集和测试集 v2）：它给不出证据引用，报出的价格也无从核实。这里有两点保留：`pure_llm` 用的是不带工具的 DeepSeek，不是豆包；而且到了 2026 年，豆包和 Kimi 都已经能通过 MCP 接入持牌数据。它们的数字准确率比 FinSight 高还是低，**目前不知道**。回答这个问题需要做[下文设计的对比测试](#公平的对比测试设计好了尚未执行)，这个测试还没有做。

## 背景：2026 年发生了什么

通用助手已经不再是“没有数据的聊天机器人”。借助 MCP 和 Skills，它们现在可以直接调用持牌金融数据库：

- Kimi 在 2026 年 4 月宣布接入同花顺 iFinD [S21]，9 月 17 日又发布金融行业解决方案，通过 MCP 接入 Wind、东方财富、标普全球、财联社、财新等数据源 [S20]。
- 豆包可以调用东方财富妙想 MCP（基于 Choice 数据库的 12 个工具，2026-09-09）[S16] 和通达信 MCP [S10]。据第三方测评，电脑端“豆包工作”的金融数据插件打通了 Wind、同花顺、中经数据 [S17]。
- 数据商也纷纷向 Agent 开放：同花顺 iFinD 推出 API 和 MCP [S10][S7]；万得 5 月上线 AIFin Market，提供数据 MCP 和 Skills [S27][S28]；东方财富 6 月上线妙想 MCP 和妙想 Claw [S34]。

所以，公平的对比不是“有数据的 FinSight 对没数据的豆包”，而是“开源、可度量的证据链路，对数据更好、但准确率没有公开的闭源产品”。

## 这些产品明显更强的地方

- **数据**：持牌、实时、覆盖面广，包括 A 股、港美股、基金、债券、宏观、券商研报、公告。FinSight 用的是会限流的免费接口（审计时东方财富直接拒绝了本机连接），没有 Level-2 行情，也没有持牌研报库，评测只覆盖 7 只标的。
- **交付深度**：能产出带公式的 Excel、PPT、完整研报，还有技能市场（Kimi 有 9 个金融技能和 118 个套件技能 [S20]，万得有技能广场 [S25]）。FinSight 只写简短的带引用回答。
- **规模与真实使用**：问财日活超过 500 万 [S3]；Kimi 称已有数十家金融机构接入 [S20]；万得服务机构客户约 30 年 [S26]。FinSight 没有生产用户。
- **牌照**：同花顺列有投资咨询资质 [S6]，可以合法提供投资建议。FinSight 没有牌照，所以设计上就拒绝给建议。
- **产品形态**：有移动端、微信入口 [S26]、多模态输入、图表和成熟的界面。
- **模型**：它们使用自研或前沿模型，部分做过金融预训练 [S2]。FinSight 在线评测只覆盖了一个模型族（DeepSeek V4.1 Flash）。

## FinSight 的不同之处，以及证据

下面每一条都只是在 FinSight 自己身上测出来的，没有一条是说它胜过某个我们没测过的产品。

1. **数字级校验，并且公开误差率。** 按句子绑定引用的校验器误放率为 1.94%（重新设计前是 33.3%；`evaluation/results/verifier_stress.json`，commit `9f0e46b`），公司间互换数字 0.53%，正确答案通过率 100%（[评测报告](../agent-eval.md#verifier-stress-test-202-gold-answers-3399-corrupted-variants-verifier_stressjson)）。其他产品都说自己“可溯源”，但都没有公开可比的比例。这只能说明它们没被量化过，不能说明它们更差。
2. **为什么检索加校验是前提：用我们自己的基线来看。** `pure_llm`（DeepSeek V4.1 Flash，不接工具）在开发集和保留集上的任务成功率都是 0.000，必需事实的引用率 0.000，草稿通过证据校验的比例只有 0.289 / 0.208。但它依然会写限定语（0.865 / 0.939），也基本不给交易指令（0.977 / 1.000）。也就是说，通用模型可以说得很谨慎，给出的内容却没有一句能核实。接入工具和校验后，Agent 路径达到 0.986 / 0.956（[评测报告](../agent-eval.md#development-set-207-tasks-220-turns)）。保留意见：这个基线代表的是“不带检索的聊天机器人”，不是对豆包或 Kimi 的测量，它们都有搜索和数据插件。
3. **合规是代码关口，而且量化过。** 模板答案和 LLM 答案经过同一个最后节点。无交易指令比例 0.999 / 1.000，唯一的失败案例也点名写在报告里（`创业板ETF能不能梭哈`）。
4. **评测公开、可复现。** 任务集（开发集 207 + 保留集 53）、工具快照、评分代码、命令、commit、网关账单口径的成本、pass^3 全部公开。失败也公开：保留集提示注入攻击在 LLM 路径上 128 次成功了 3 次，其中一次是往新闻里植入的假收盘价，因为它**确实**出现在所引用的证据里，所以通过了数字校验（[评测报告](../agent-eval.md#known-failures-and-root-causes)）。
5. **可自托管，可降级。** MIT 协议，支持 Docker 和 Kubernetes。没有 LLM Key 时，确定性路径照样给出带引用的答案，成功率 0.981 / 0.849，成本为 0。
6. **协议。** 工具通过 MCP 对外提供，整个 Agent 通过 A2A 1.0 对外提供（追问对应 `input-required` 状态）。其他产品都开放了 MCP 或 Skills，但我们没有查到任何一家公开 A2A 端点。
7. **路由可解释，全链路可追踪。** 每次运行都记录路由原因、工具、token、成本和 Prompt 哈希。

FinSight 自己的局限同样要说清楚：在线评测只用了一个模型族；保留集参与了 Prompt 选择；校验器无法判断选的报告期或指标对不对；关键词注入过滤不泛化；Agent 路径 P95 延迟约 25 秒（见 [README 局限](../../README_CN.md#局限)）。

| 数据缺失 | 3 | 已退市标的，或尚未披露的数据 | 必须说明拿不到，不能编造 |
| 多轮追问 | 2 | “那它的 PB 呢” | 正确承接上一轮的标的 |

**执行方式。** 固定一个交易日 T，所有产品在同一时间窗口内提问，即 T 日收盘后、下一个交易日开盘前。每题用新会话、默认设置问 3 次；产品如果有金融模式或插件，再在开启状态下问 1 次。保存原始回答和截图。两名标注员在不知道产品名称的情况下打分，分歧逐条裁决，并报告 Cohen's kappa。

**指标（先按每个数字统计，再按每个回答统计）：**

- **引用覆盖率**：带可识别来源（链接、文件或注明日期的数据集）的数字所占比例。
- **与所引来源一致**：数字和它引用的来源在写出的精度内一致。报告期或指标选错也算错。
- **与标准答案一致**：数字和交易所或定期报告的数值一致。这一项能抓出“可溯源但错误”的数字，比如 FinSight 被植入假收盘价的那次失败。
- **合规违规**：每个回答里出现明确买卖判断、目标价或仓位建议的次数。附免责声明不能抵消违规。
- 次要指标：数据缺失时是否如实说明、该拒答或该追问时是否做对、延迟，以及能看到的每题成本。

**分析。** 每个产品、每项指标报告 Wilson 95% 置信区间和 pass^3。n = 30 时区间宽度约 ±15 个百分点，所以这只是一个筛查性测试，能发现大的差距（比如一半的数字没有来源），分不出接近的对手。对于 FinSight 数据覆盖不到的题目，应当预期持牌产品表现更好。

**什么结果会改变本页的结论。** 如果某个产品在这 30 道题上的引用覆盖率和“与所引来源一致”都不低于 FinSight，上面第 1 条就要改成“两者持平，但 FinSight 是开源的”，FinSight 的价值也就收窄到开源、可自托管和协议开放这几点。
