# FinSight 面试讲稿

一页纸版本，用于项目介绍和追问准备。每个数字都能指到仓库里已提交的文件（`evaluation/results/`、`docs/results/`），文件记录了 commit、Prompt 哈希和运行命令。更完整的取舍与失败案例见 [设计复盘](agent-design-notes.md)。

## 1. 30 秒介绍

> FinSight 是一个面向 A 股的证据优先研究 Agent。经典、可解释的 NLU 负责理解问题、守卫和路由；LLM 在 LangGraph 循环里调用 9 个类型化的取证工具（行情、基本面、宏观、公告、新闻等）。答案里的每个数字都由代码逐句对照本句引用的证据核对，最后由合规节点删掉任何像投资建议的内容。没有 LLM 时同一张图用确定性规划器作答。
>
> 这个项目我最想讲的是评测：我请独立的作者另写任务集，首次运行的数字原样提交。路由在我自己写的标注上是 98.8%，在独立标注上只有 74%。之后按类别修复，再用一套新的独立标注测一次，是 80%。

## 2. 两分钟架构讲解

按一次请求的路径讲，边讲边画：

1. **`guard_in`（守卫与路由）**：
   - 输入守卫先剥掉用户消息里的指令类文本（「忽略之前的规则」）。
   - 经典 NLU 识别实体和意图；会话规则处理追问：代词「它」、复数「这两家」、指代组「前者/后者」、省略「ROE呢」。
   - 可解释的路由器给出四种去向：拒答（非金融、只有改设定的指令、加密资产/美股）、澄清（没有标的）、固定流程（单一事实）、Agent（对比、归因、判断、宏观到市场）。
   - 每个决定写一个理由代码，进 trace。
2. **两条回答路径**：
   - 固定流程：确定性规划器决定调哪些工具，模板或 LLM 组织答案。
   - Agent：LLM 在工具循环里自己选工具；规划器会先预取显然需要的工具，所以很多问题一次 LLM 调用就答完。
   - 两条路径都有步数、工具数、token 和截止时间预算。
3. **`verify`（校验）**：
   - 答案里的每个数字必须出现在本句引用的那条证据里，按单位、写出的精度和正负号匹配。
   - 不通过先做引用修复（只有一条证据含这个数时补上 id），仍不通过让 LLM 修改一次，再不通过就整句删除。
4. **`compliance`（合规）**：软化判断和因果措辞，删除交易指令与仓位建议，补数据新鲜度提示与免责声明，检查回答语言。
5. **降级**：没有 Key、模型故障、预算耗尽、超过截止时间，都落到规划器 + 模板，仍然有引用、仍然经过校验，并在 `degraded` 里说明原因。
6. **周边**：
   - LangGraph checkpointer 保存会话（内存 / SQLite / Postgres），澄清时 `interrupt()` 暂停、`/agent/resume` 恢复，多副本共享。
   - 工具同时经 MCP 提供，整个 Agent 经 A2A 1.0 提供。
   - trace 进 Prometheus、OTLP、审计日志。

## 3. 三个可以当场辩护的数字

### 数字一：校验器误放率 1.94%

- **方法**：取开发集上 202 个校验通过的正确答案，自动生成 3,399 个篡改变体：数字改动 1%、5%、20%，或把另一家公司的数字换进来。统计校验器把篡改答案当作正确答案放过的比例。
- **结果**（`evaluation/results/verifier_stress.json`，`9f0e46b`）：
  - 原来的整批比对误放 33.3%，运行级比对 24.4%，逐句绑定 **1.94%**；
  - 公司之间互换数字：100% → **0.53%**；
  - 正确答案 100% 通过。
- **局限**：
  - 1% 的改动有 3.5% 仍会放过，因为写出的精度本身就有容差。
  - 同一条证据里有多个报告期时，无法判断选对了哪一期。
  - 投毒到新闻正文里的假数字能通过：校验证明的是可追溯，不是真实。
- **复现**：`python -m evaluation.agent_eval.verifier_stress`

### 数字二：路由 0.988 / 0.740 / 0.801（首次运行 vs 暴露后）

- **方法**：
  - 独立作者只看四句路由策略，写了 154 条标注，没有看路由代码。
  - 首次运行只有 **0.740**，同一份代码在我自己的 162 条标注上是 0.988。
  - 按错误的类别修复之后，独立 v1 达到 1.000，但那是暴露后，不是估计。
  - 于是再请另一位作者写 241 条新标注，只跑一次：**0.801**。
- **文件**：
  - `router_eval-independent_v1-first-run.json`（`882745d`）
  - `router_eval-round4-independent-after-exposure.json`
  - `router_eval-independent_v2-first-run.json`（`3080bfe`）
- **为什么可信**：
  - 集合先提交再运行，sha256 写在编写说明里。
  - 首次运行的结果原样提交。
  - 自有标注里新增的例子会用测试检查，不与独立集合、各测试集重复。
- **误差线**：241 条上 0.801 的二项 95% 区间约 ±5 个百分点。
- **局限**：独立作者也是按书面规则写的 AI 编写者，不是真实用户日志；v2 里有 4 条与自有标注碰巧相同，已在结果文件里注明。

### 数字三：Agent P95 27.1 → 15.4 秒，成功率不降

- **方法**：
  - DeepSeek V4.1 Flash，保留集 / 测试集 v2，每任务重复 3 次，走 UI 同样的 SSE 流式路径，记录首字时间。
  - 先剖析：95% 的时间花在 LLM 往返上；一半答案多做了一次修改调用，而其中多数是校验器的数字切分 bug（`20.9x` 被读成 20）造成的误报。
- **改动**（每项都有开关）：
  - 修复数字切分；
  - 连接池；
  - 只缺引用时先做引用修复，不再让 LLM 改；
  - 20 秒卡顿超时；
  - 规划器预取工具。
- **结果**（`docs/performance.md` §2a，`perf-*.json`）：
  - P95：保留集 27.1 → **15.4 秒**，测试集 v2 24.2 → **17.3 秒**；
  - 首字 P50：约 5.5 → **3.0 秒**；
  - 每轮 LLM 调用：2.30 → 1.39；
  - 与关闭开关的同一份代码配对比较，成功率 Δ +0.006 [0.000, +0.019]（保留集）、+0.003 [−0.005, +0.014]（测试集 v2）。
- **代价**：
  - 预取让「必要工具占比」从 0.684 降到 0.675（保留集）。
  - 允许派生数字让互换数字的误放率从 0.53% 升到 0.93%。
  - GLM 的 P95 仍是 60–70 秒。

## 4. 一个失败故事：独立多轮集 0.224

- **发生了什么**：
  - 我请一位没读过路由和记忆代码的作者写了 49 段多轮对话。
  - 第一次跑（无 LLM），任务成功率只有 **0.224**，轮次 0.709；DeepSeek Agent 也只有 0.361。
  - 失败集中在：
    - 金融对话里不点名的追问被当成离题拒答（「MA5是多少？站上了吗？」）；
    - 「三家里哪家」「前者/后者」解析不了；
    - 行业问题拿宏观数据回答；
    - 模板忽略最高价、成交量这类细节；
    - 追问里的判断题没有加限定语。
- **根因**：规则是按我自己能想到的说法写的，我的开发集和标注也是我写的，所以 0.988 这类高分衡量的是「规则和作者一致」。
- **怎么处理的**：
  1. 首次运行的数字原样提交（`multiturn_v1-auto-nollm-first-run.json`、`ablation-multiturn_v1-deepseek-first-run.json`）。
  2. 每类失败先写新的开发集风格例子，再写通用规则，每条规则带理由代码。
  3. 修复后在这个集合上是 1.000，但一律标注「暴露后」。
  4. 能说明泛化的，是没有参与调参的集合：保留集 0.906 → 0.925；再加上新写的独立路由标注 v2（0.801）和从未用于修复的测试集 v3。
- **我学到的**：独立评测的价值只在第一次运行，那个数字必须提交。评测还必须能分辨答案出自模型还是出自兜底路径：有一次网关周额度用完，Agent 全部降级，分数和固定流程一模一样，我后来让评测工具把 429 占比过高的运行标为无效。

## 5. 常见追问

**为什么不用多 Agent（分析师、交易员角色辩论）？** 这个场景的价值在证据链，不在观点多样性。多角色会让成本和不可控性成倍增加，而校验是确定性代码，不需要另一个 LLM 来「审」。在我自己的数据上，单 Agent 工具循环都没有显著胜过「固定流程 + LLM 组织答案」，再加角色更难证明值得。

**为什么用经典 NLU 而不是全部交给 LLM？** 路由和守卫要可解释、便宜、离线可测：每个决定都有理由代码，确定性路径零 token、0.4 秒。LLM 只用在它有价值的地方，也就是选工具和组织语言。代价是规则会过拟合作者的措辞，这正是我用独立标注去测、并把 0.740 写进 README 的原因。

**幻觉怎么量化？** 分两层：
- 线上：每个答案统计「无法由所引证据支撑的数字」，逐句检查，不通过就修改或删除，trace 里有记录。
- 离线：用压力测试量化校验器本身的可靠性（数字一）。

另外，纯 LLM 不调工具时，在 511 个任务上一题都过不了，这说明工具加校验是前提。

**成本和延迟怎么控？**
- 路由把简单问题分到零 token 路径；
- 按节点设推理强度；
- 规划器预取工具，减少往返；
- 强制收尾时保留同一份工具定义、用 `tool_choice="none"`，维持缓存前缀；
- 每次 LLM 请求都受运行截止时间约束（90 秒 + 作答宽限 20 秒，低于接口的 120 秒超时）。

DeepSeek Agent 单任务约 $0.0008–0.0013，4 并发压测每 1,000 次提问约 ¥12.6。

**安全怎么做？**
- 结构优先：工具只读；工具结果包在不可信数据信封里；数字必须来自证据；合规节点删除交易指令；用户消息先过输入守卫。
- 关键词过滤只是纵深防御，我用没见过的攻击集证明了它不泛化（holdout3 上只拦下 27%）。
- 红队结果：在线开发集三条路径都是 0/72；离线 holdout3 2/88。
- 工程侧：API Key 隔离会话、限流、请求体上限、只读根文件系统、gitleaks 全历史扫描、NetworkPolicy。

**如果重来会怎么做？**
1. 第一天就请独立作者写测试集和路由标注，而不是先调到自己的集合 0.99。
2. 路由类别用小型分类器，由独立标注训练和衡量，替代越来越长的词表。
3. 评测从一开始就区分「模型回答」和「降级回答」。
4. 更早接入第二个模型，并准备更高的网关配额。

## 6. 白板题提纲

- **路由决策**：输入守卫 → NLU → 会话改写（指代 / 省略 / 组引用）→ 覆盖范围检查（加密、美股）→ 按优先级判定：拒答 > 澄清（没有标的、悬空指代、没有标的的建议）> Agent（对比、归因、判断、宏观到市场、多方面分析）> 固定流程。每一步写理由代码；没有 LLM 时 Agent 降级为固定流程。
- **校验绑定**：按句切分 → 抽取数字（单位倍数、写出的精度、正负号；日期、期限、编号不算）→ 找本句引用的证据 id → 在该证据的数值里按单位倍数和容差匹配 → 市场指标优先取行情来源 → 不通过的句子：先做引用修复，再让 LLM 修改一次，再整句删除，全部删完就回退模板。
- **图的节点**：`guard_in → (refuse | clarify | execute_plan → compose | agent_llm ⇄ agent_tools) → verify → (revise) → compliance → finalize`。状态里每轮字段用可重置 reducer 清空；`durability="exit"` 每轮只写一次检查点。

## 7. AI 编程工具的使用说明

这个项目是在作者的主导下，大量借助 AI 编程助手（Claude Code）完成的：作者定目标、做取舍、审阅结果，代码、测试和文档的大部分由助手在作者指导下编写。面试时建议主动说明这一点。

- **作者本人必须能讲清、能手写的内容**：
  - 路由的四种去向与优先级；
  - 校验器的句子绑定和单位、精度、正负号匹配；
  - LangGraph 图的节点与状态清理；
  - 降级链；
  - 评测口径（一票否决、pass^k、bootstrap 与配对比较）；
  - 「首次运行 vs 暴露后」的区别；
  - 上面三个数字的来源和局限。
- **结论是怎么独立核实的**：
  - 另开的 AI 编写者在不看代码的前提下写任务集和路由标注，写好先提交再运行。
  - 另开的评审 Agent 按招聘场景的评分表逐项打分，自己写未见过的攻击和问题，并在真实浏览器里验证界面。
  - 每个数字都对应一个已提交的结果文件，CI 检查文档与结果一致。
- **不要夸大**：独立集合的作者也是 AI，不等于真实用户；在线评测只覆盖两个 flash 级模型；与问财、豆包的对比测试只做了设计，没有执行。
